# Port the Herdr patch to 0.9.x with a machine-toggle key

**Status:** Complete
**Scope:** `herdr/` (patch, base config, spaces-env plugin), `bin/.local/bin/install-herdr-focus`, README/ARCHITECTURE/VERIFICATION; the installed `~/.local/bin/herdr` and the saved SSH machine profile `home`.

## Objective

Run Herdr 0.9.x with the same sidebar/pane behaviour as the pinned 0.8.2 patch
(inline Spaces tree with gap rows, `sidebar_hidden` filtering, no Agents panel,
fixed footer, pane chrome) **and** the new multi-machine feature, so that:

- `prefix+;` still toggles the Personal/Work environment on the selected machine,
  and `prefix+:` still sends the current Space across.
- `prefix+'` switches the client between Local and the saved SSH machine `home`
  (`ericzheng@erics-macbook-pro`), cycling through every online machine, and
  replaces the interim full-screen `herdr-home` popup on the same key.

## Non-goals

- Changing spaces-env semantics or making environments span machines. Each
  machine keeps its own server, plugin state and environment assignments.
- Live handoff from the running server. Deployment follows the natural-restart
  path in the README unless explicitly requested.
- Windows or mobile-layout parity for the tree.

## Context and constraints

- 2026-09-11: `herdr update` replaced the patched 0.8.2 binary with stock 0.9.0.
  The stock binary ignores `ui.focused_pane_heavy_borders`,
  `ui.dim_unfocused_panes`, `ui.unfocused_pane_opacity` and
  `ui.sidebar.spaces.inline_agents`, and the `sidebar_hidden` token, so every
  Space and the Agents panel reappeared. The plugins themselves kept working
  (`agent.view.set`, `workspace.report_metadata`, `workspace.focus` all succeed
  on 0.9.0). The patched 0.8.2 build was reinstalled the same day; stock 0.9.0
  is kept at `~/.local/bin/herdr.official-0.9.0`.
- The pinned patch (`herdr/.config/herdr/patches/herdr-0.8.2-focused-pane.patch`)
  does **not** apply to v0.9.0 (`b99002a`): upstream moved the TUI out of the
  server (`src/ui/`, `src/app/input/`, `src/ui/menus.rs` are gone or hollow)
  into a per-client shell under `src/client/shell/` (~19k lines; sidebar in
  `sidebar.rs`, `endpoint_sidebar.rs`, `agent_sidebar.rs`, mouse in
  `mouse.rs`, keys in `input.rs`/`actions.rs`). Expect a re-implementation of
  the tree, hidden-token filtering, footer and pane chrome against the
  `ClientShellSnapshot`/`ShellHitMap` model, not a rebase.
- Stock 0.9.0 has **no keybinding and no plugin API for switching machines**:
  switching is a sidebar click, the navigator, `previous/next_workspace`
  (which walk every Space on every online machine) or `previous/next_agent`.
  Internally `ClientShellAction::ActivateEndpoint { endpoint_id, target }` in
  `src/client/shell/endpoint_navigation.rs` is what a new `KeybindAction`
  (e.g. `next_machine`) must emit. Plugins run server-side and cannot change
  the client's selected endpoint, so the key must be native.
- Per-machine tree: agents from other machines belong under their machine
  header, never mixed into Local's Space groups. Machine headers are the only
  rows above repository level; keep the gap-row rule (blank between groups,
  never leading/trailing) within each machine.
- `agent.view.set`'s label is rendered by the stock Agents panel header; the
  port keeps rendering it only in the fixed footer.
- The saved profile was renamed `personal` → `home` on 2026-09-11 so the
  machine label no longer collides with the Personal environment.
- Follow `docs/VERIFICATION.md` for the build-only check and never stop a
  live server for verification.

## Approach

1. Fetch v0.9.0 (`/tmp/herdr09` was a clean checkout on 2026-09-11) and map
   each 0.8.2 hunk to its new owner: config keys (`src/config/model.rs`,
   `src/config/sidebar.rs`), pane chrome (`src/ui/panes.rs`, `src/layout.rs`,
   `src/server/headless.rs` retained-row blending), sidebar
   (`src/client/shell/{sidebar,endpoint_sidebar,agent_sidebar,mouse,state}.rs`,
   `src/ui.rs` section geometry), title stripping (`src/terminal/title.rs`).
2. Add `KeybindAction::NextMachine`/`PreviousMachine` (config key
   `next_machine`, default unset) that cycles online endpoints via
   `ActivateEndpoint`; bind `prefix+'` in `config.base.toml` and drop the
   reservation comment.
3. Re-implement the row document (`TreeTarget` incl. `Gap`) on
   `ClientShellSnapshot`, per endpoint, with hit-testing through `ShellHitMap`.
4. Port `sidebar_hidden` filtering and the fixed footer; remove the Agents
   panel/New target in tree mode.
5. Update `install-herdr-focus` (commit, patch name, test list), rename the
   patch file, and run `--build-only`; then update docs and let the user
   choose the deployment moment.

## Decisions

- **Two keys, not one cycle:** `prefix+;` = environment toggle, `prefix+:` =
  send, `prefix+'` = machine toggle (user choice, 2026-09-11; the `;`/`:`
  order was flipped back the same day). A single three-way cycle was rejected
  because environments are per-machine state.
- **Interim hop via popup, not a nested pane:** a `type = "popup"` command
  receives every key in 0.8.2 (`src/app/input/mod.rs`, `popup_pane.is_some()`
  short-circuits to the terminal), so the remote client's prefix works without
  double-prefixing; a tab/pane would have fought the outer prefix. Return is
  the remote detach (`C-a C-d`), which ends the popup command.
- **Rollback first:** the user chose to run the patched 0.8.2 (no machines)
  until the port lands rather than stock 0.9.0 without the custom sidebar.
- **Machine label `home`:** avoids reading "personal" as both a machine and an
  environment in the same sidebar.
- **Client-owned disclosure state:** 0.9 keeps sidebar folds in the client
  (`collapsed_groups` preferences, new runtime-only `collapsed_space_agents`
  keyed by machine + Space id). Tree-mode startup ignores saved folds; a focus
  change opens the focused Space's group/agents before the reveal scroll.
- **Machine headers in the tree:** with more than one machine, the tree keeps
  stock's machine rows (`▾ Local`, `▾ home`) and nests each machine's tree by
  two columns with a gap row between machines; conversations never cross
  machines. Remote agent rows use `hits.endpoint_agents` so clicks activate
  that machine on the exact pane.
- **Footer shares the toggle row:** the fixed footer is `width - 2` so the
  `«` toggle never overwrites `menu`.
- **`herdr-home` kept, unbound:** cheaper than a stow removal and still useful
  from a plain terminal; default client is now `~/.local/bin/herdr` because
  the ported build shares the 0.9 protocol.
- **Server tests only where behaviour is server-side:** the three 0.8.2
  `app::tests::reload_config_*`/`handoff_*` disclosure tests were dropped
  (state moved client-side) and replaced by `client::shell::tests::tree`.

## Risks and recovery

- The patch is pinned to `b99002a`; `herdr update` will replace the binary and
  a newer upstream release needs a fresh port. Recovery: rerun
  `install-herdr-focus` (or `cp ~/.local/bin/herdr.official-0.9.0 ~/.local/bin/herdr`
  to return to stock).
- Pane chrome needs the rebuilt server; until the stock 0.9.0 server restarts
  naturally, a patched client shows the tree/footer/machine keys but stock pane
  borders and no fading.
- Mobile layout and the collapsed multi-machine sidebar keep stock rendering
  (hidden Spaces are filtered there too, but no tree).
