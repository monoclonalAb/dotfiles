# Preserve Herdr customizations on 0.9.1

**Status:** Complete (live handoff verified; attention-state caveat and visual follow-up below)
**Scope:** Herdr patch, pinned installer/update behavior, operator docs, installed local binary and explicitly approved local live-server handoff.

## Objective

Update the user's Herdr 0.9.1 to retain the custom features from 0.9.0 without silently losing them on another stock update.

## Non-goals

- Change keybindings, plugin state, environment assignments or Pi configuration.
- Restart/disconnect live clients, hand off the server, or modify the remote machine without explicit approval.
- Automatically trust/rebase arbitrary future upstream changes.

## Context and constraints

- Worktree contains extensive unrelated and overlapping prior changes; preserve them.
- At start, installed binary and running server reported stock 0.9.1, protocol 22; config check ignored next_machine, inline_agents and three pane-chrome keys. Post-install state is recorded below.
- Upstream v0.9.1 resolves to `065ef9d6a531c49fb8bee7e818ef837065b21ee9`; previous pin is `b99002ac99b09e00b4ca692436cb15a6b0d676f1`.
- Existing 0.9.0 patch includes the pending click-review fix; preserve it and its regressions. See [click-review plan](2026-09-22-herdr-click-review.md).
- Generated config and binaries stay outside Git; canonical config is unchanged unless evidence requires a migration.

## Decisions

- Preserve existing source-owned configuration rather than copying runtime config back into Stow.
- A stock update must not erase custom features; future releases still require an audited patch, not an automatic blind rebase. The custom updater rejects replacement before I/O and directs the user to `install-herdr-focus`; binary identity includes `dotfiles.<patch-hash>`.
- 0.9.1 already contains the click-review native fix (`emit_focus_api_events` visibility and client navigation delivery). Keep its regression tests without duplicating the upstream fix.
- Preserve 0.9.1's atomic dirty-patch snapshots and endpoint/generation-aware navigation. Adapt custom fade/tree to these APIs; scope repository folds per endpoint and keep Navigate previews machine-local in tree mode.
- Upstream now requires Zig 0.16.0, not 0.15.2. Updated Brewfile/installer. Verification uses the official aarch64-macos 0.16.0 archive in `/tmp`, verified SHA-256 `b23d70deaa879b5c2d486ed3316f7eaa53e84acf6fc9cc747de152450d401489`; no system Zig replacement.

## Risks and recovery

Client chrome activates on a fresh attach (`herdr`); server pane chrome is now on the custom build. Never stop a server holding active panes. Stock/custom binary and config backups are in the deployment directories above; restoring files alone does not change a loaded server. Normal `install-herdr-focus` now needs Zig 0.16.0; the system's existing 0.15.2 was not replaced, and this build used the temporary explicit `ZIG` override. Native handoff does not preserve every transient metadata/attention detail (Q-007).
