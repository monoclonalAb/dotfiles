# Run Opus 5.5 through Pi with recurring startup maintenance

**Status:** Complete
**Scope:** Pi's OMP Anthropic route, OMP-only installation prerequisite, focused regression/live checks and owning docs.

## Objective and authority

Make sure **`anthropic/claude-opus-5-5`** runs on Pi; another model does not satisfy
this objective. The user then explicitly approved the recurring startup workflow:
apply reviewed OMP/bridge updates, run a quota-limited model probe, and stop clearly
for unreviewed releases. This includes the real OMP upgrade and synthetic live
requests here, not unrelated package upgrades or input to existing panes.

## Context and earliest failed handoff

Pi 0.87.1 had Opus 5.5 in its catalog, but OMP 18.1.5 and the bridge advertised
Claude Code 2.1.257. Anthropic rejected it with `claude_code_version_too_old`,
requiring 2.1.280. Previous Fable/Sonnet/Haiku successes were not Opus 5.5 evidence.

The original startup implementation narrowed maintenance to equality with a local
pin. Two stale matching versions skipped upgrades, and diagnostic `active` meant
only prerequisites. The owner was the extension's update/proof workflow, not a
missing blanket agent instruction. A diagnostic-only correction exposed the gap;
it did not implement automatic maintenance. This follow-up implements the approved
workflow at that owner without pretending unreviewed source can migrate itself.

## Implementation and review decisions

- **Reviewed pair:** OMP v18.2.11 at commit
  `e4151593ace2781d1dc2f06d760301f88af3e9dc`, Claude Code 2.1.280 / SDK 0.112.1.
  Compared the fingerprint, headers/betas, billing salt/XXHash seed, identity,
  bootstrap, tool naming, cache policies and provider diff with v18.1.5.
- Bootstrap model remains Opus 4.8; it is an identity endpoint parameter, not an
  inference fallback. Client version advances in User-Agent and billing together.
- Added reviewed non-deferred tool-head caching and the extended-cache-TTL beta.
  Retain Pi-selected TTL, bounded two-message tail caching and native transcript
  serialization; do not transplant OMP's full cache decimation/compaction plane.
- **No runtime code fetching:** the bridge implementation is shipped in source;
  newer protocols require review/deployment. No automatic adoption of a version
  from server error text. Current source and binary must match the reviewed pair.
- Latest-release HEAD redirect avoids the GitHub API's observed unauthenticated
  403 rate limit. Only a canonical HTTPS stable-release URL is accepted.
- Refresh only the clean official OMP Homebrew tap; verify the full formula hash,
  fast-forward only, disable Homebrew auto-update/cleanup, then upgrade OMP only.
  Formula SHA-256 is pinned beside the protocol version in `transport.ts`.
- Resolve selected auth at startup: Pi's synchronous availability snapshot can be
  stale immediately after provider registration. Never scan accounts or infer
  the route from model name alone. OMP continues to own its credential lifecycle.
- A changed OMP access credential requires reload/reverification; no probe from
  another credential is reused. Probe state and credential fingerprints are memory-only.
- Failed checks are not a reason to use native Pi/another model/account. Probe
  limits are visible; normal prompts reuse the result. Reload starts a new check.

## Limits and recovery

This private OAuth wire route is not an Anthropic-supported integration and does
not prove quota/billing attribution or every model entitlement. Startup tests
consume quota outside conversation totals. An unavailable freshness service or
unreviewed new release intentionally blocks the route until repaired/reviewed.

No app restarts, wildcard Stow, other-pane input, commits or pushes occurred.
Existing production source files are leaf symlinks; no new runtime file or package
restow was needed. Existing idle Pi sessions need a user-initiated `/reload` to use
this implementation. Inspect the owner of a stale update lock before recovery;
never delete a lock while its updater may still be running. Roll back source and
binary as a reviewed pair, not just the fingerprint or just the executable.
