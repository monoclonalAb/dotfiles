# Connect Pi to the existing read-only GCP MCP servers

**Status:** Complete (configuration verified; user reauthentication and Pi reload remain)
**Scope:** Pi global MCP registration and operator documentation; bounded local/server checks.

## Objective

Expose the existing Google-authored gcloud and Observability MCP servers in Pi,
using the same pinned packages and gcloud allowlist as OMP.

## Non-goals

- No cloud mutations, IAM changes, API enablement, project-default changes, or new credentials in Git.
- No OMP changes, package upgrades, broad Stow deployment, or other-session reloads.

## Context and constraints

- `pi/.pi/agent/mcp.json` is already stowed and contains concurrent/untracked work; preserve existing servers.
- OMP already registers both servers. Their pinned npm packages and gcloud CLI are installed.
- Reuse `omp/.omp/agent/gcloud-mcp-allowlist.json` without duplicating or widening it.
- The user has not selected a project or requested write access. Project-specific queries remain out of scope.

## Acceptance criteria

- [x] Pi's effective config enables both pinned servers with lazy startup.
- [x] Both servers complete stdio initialization and tool discovery.
- [x] gcloud reports the shared allowlist and rejects a harmless non-allowlisted command.
- [x] Document authentication prerequisites, explicit project selection, and Pi reload steps.

## Approach

1. Add only the two registrations to Pi; preserve the current worktree.
2. Verify config merging, server handshakes, and the allowlist without cloud mutations.
3. Check authentication without emitting credentials; report any login/manual reload gap.
4. Update owning docs and inspect final diff/status.
